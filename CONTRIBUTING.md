# Contributing and sharing improvements

PortGuard Mini welcomes forks, security fixes, testing, documentation, and independent variants.

## Make your improved version discoverable

1. Fork https://github.com/Fort-fog/PortGuard-Mini on GitHub.
2. Make your changes and test them (`go test ./...`, `go vet ./...`).
3. Push your commits to your fork. Describe what changed, and include instructions to reproduce your results.
4. **Optional but encouraged:** Open a pull request to add your fork's URL and a short description to [COMMUNITY-FORKS.md](COMMUNITY-FORKS.md), even if you do not want to merge the code into the main project.
5. If you want your change included upstream, open a pull request with the actual code as well.

You do **not** need to send a private message to the original author. You retain credit for your work. Upstream inclusion is reviewed and not automatic.

## License and attribution

This repository's new contributions are accepted under **GNU GPL v3.0 only**. If you distribute a modified GPLv3 version, identify your modifications, preserve required notices and provide the corresponding source to recipients under GPLv3. GPLv3 does **not** require releasing private changes, publishing a GitHub repository, or notifying the original author.

Please do not add proprietary or incompatible-licensed code. Identify third-party materials and their licenses. Contributors should have the right to submit their code under GPLv3.

## Security reports

Do not publicly publish working exploitation steps or private credentials. Use GitHub's private vulnerability reporting feature if enabled, or first open a non-sensitive issue asking how to report privately. Never include real VPS addresses, credentials or private keys in issues.
