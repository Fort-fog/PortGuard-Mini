# PortGuard Mini v0.8.3 — исправления ошибок v0.8.2

Только корректирующий релиз, без изменения назначения программы и без новых внешних Go-модулей.

## Исправлено

- `apply`: записывает точно запланированное содержимое, а не угадывает его по подстроке пути. PHP Apache SAPI больше не получает директивы Apache. Используется `;` в новых PHP INI, старый маркер `#` по-прежнему распознаётся.
- Проверка и reload затрагивают только службы, относящиеся к действительно изменённым файлам. Учитывается Apache SAPI. Исправлено имя бинарника PHP-FPM в Debian/Ubuntu: `php-fpm8.x`, а не имя systemd-службы `php8.x-fpm`.
- При неподдерживаемом DebianBanner либо ошибке получения эффективной настройки SSH эта часть плана пропускается с предупреждением; настройки SSH-авторизации не изменяются.
- `rollback`: предварительная проверка всех файлов, отказ от удаления чужих файлов и ссылок, восстановление удалённых файлов при ошибке. Нет вызовов валидации отсутствующих Apache/Nginx, если их изменения не затронуты. При ошибке reload файлы восстанавливаются, повторный reload выполняется с сообщением об ошибках восстановления. В обоих режимах сохраняются права существующих файлов.
- Аудит целостности продолжает обход при ошибке отдельного файла, выдаёт `ALERT SECURITY UNREADABLE`, не принимает неполный снимок как эталон. Экранируются пути и ошибки в сообщениях об отдельных файлах. Не объявляет удалёнными потомков недоступного каталога.
- Чтение обычных файлов использует `O_NOFOLLOW`, `O_NONBLOCK`, проверку открытого дескриптора и ограничение в 16 МиБ. Это снижает риск подмены файла и блокировки аудита, но не является полной защитой от гонок в родительских каталогах или от атакующего с root.
- Оба baseline записываются атомарно с правами 0600, не заменяя существующий эталон. Формат старых эталонов совместим; команда принятия изменений не добавлена.
- При переполнении очереди inotify или потере наблюдения watcher завершает работу с ошибкой, а штатная `Restart=on-failure` политика systemd восстанавливает наблюдение. Аудит остаётся независимым. При ручном запуске наблюдатель нужно перезапустить самостоятельно. В промежутке могут быть пропущены события.
- Отсутствие необязательного, неустановленного event watcher выводится как примечание, если systemd подтверждает `LoadState=not-found`.
- Установщики не перезаписывают существующие программы/службы; очищают собственные файлы при незавершённой новой установке. Откат установки выполняется по возможности, ошибки очистки отображаются.

## Не менялось

Назначение и схема программы, перечень наблюдаемых путей, интерфейс ручных команд, режимы hardening, отдельный ручной аварийный режим, отсутствие автоматического выключения, штатный read-only аудит, его частота и содержание systemd unit-файлов. Fail2ban, nftables, SSH-авторизация, сайт и пользовательские эталоны не меняются. Новых функций, облака, БД, Telegram, webhook и фреймворков нет.

## Проверка и сборка

Выполнить `go test ./...`, `go vet ./...`, `go test -race ./...`. Регрессионные тесты используют временные файлы и подставные команды; не редактируют настоящие конфигурации системы. Сборка: Linux amd64 и arm64, CGO отключён. Проверка на реальных запущенных службах Apache/Nginx/PHP-FPM/systemd необходима перед эксплуатацией hardening; тесты не гарантируют безопасную работу на каждом дистрибутиве.

## Обновление существующего сервера

Не запускать установщики повторно. Сначала проверить новый бинарник отдельно, сохранить резервную копию старого, затем отдельно заменить только бинарник и перезапустить наблюдатель. Существующие unit-файлы, таймеры, ключи, security.json и ports.json не сбрасывать. Никакого автоматического запуска `apply`, `watch` или аварийного отключения сервера.
